# 攻击历史汇总（样例 · 已脱敏）

> **这不是任何一台机器的真实记录。**
>
> 真实报告由 `tools/attack-report.py` 在**本机**生成，默认写到
> `/var/lib/vigil-dashboard/` 下，**故意不进仓库**。两条原因都必须遵守：
>
> 1. 真实报告里是**第三方**的地址与探测路径。把它们提交进公开仓库，等于
>    替攻击者留档，同时把来访者的信息一起发布出去。
> 2. 报告还暴露这台机器被打了多久、被什么打 —— 那是对外情报。
>
> 本文件的地址全部取自 RFC 5737 文档段（`192.0.2.0/24`、`198.51.100.0/24`、
> `203.0.113.0/24`），它们不可能是真实来源。发布关卡
> （`vigil/core/sourceaudit.py`）同样会拒绝任何真实公网地址字面量，所以
> 这份样例只能这样写 —— 这既是纪律，也是关卡强制的。
>
> 生成真实报告：
>
> ```bash
> python3 dashboard/tools/attack-report.py \
>     --out /var/lib/vigil-dashboard/attack-history.md
> ```
>
> 它会把模拟/内网/本机记录剔除，并在总览里列出排除计数。
