# 自带的状态与反馈页面

`vigil web` —— 一个**只监听本机**、由已有 Web 服务反代对外的实时状态页。
不用等告警邮件才知道机器现在怎么样。

## 两个页面，两种用途（v3.2.0 起）

vigil 现在带**两个**网页，互不依赖，可以只装一个，也可以同时开着：

| | `vigil web`（本页） | 内置管理后台 `dashboard/` |
|---|---|---|
| 定位 | 最小：状态、检查项、诱饵命中、反馈入口 | 完整：实时态势地图 + 管理控制台 |
| 内容 | 本机状态卡片、最近检查、反馈框 | 世界地图上的访问流星、攻击分级、站点一键开关、全盘文件管理、操作审计 |
| 进程 | `vigil-web.service`（默认 `127.0.0.1:9177`） | `vigil-dashboard.service`（默认 `127.0.0.1:9310`） |
| 部署 | `sudo vigil setup`，或 `vigil web install --domain ...` | `sudo bash dashboard/deploy/install.sh` |
| 配置 | `vigil web` 系列子命令 + `config.json` | `dashboard/config.json`（模板 `dashboard/config.example.json`） |
| 依赖 | 只用标准库 | 只用标准库（GeoIP 复用面板自带 mmdb） |
| 对外 | 自己生成反代配置 | 自己生成反代配置 |

**分工的理由是运维手感，不是技术。** 状态页回答「机器现在还好吗」，要能在
任何一台刚装上的机器上一路回车就跑起来；管理后台回答「谁在打、我要不要关掉
这个站点、那个文件改没改」，它需要地图、GeoIP、站点开关与全盘文件权限，
装它是一次明确的决定。把这两件事塞进一个页面，只会让最常用的那个变复杂。

**两者不会互相覆盖**：端口、systemd 单元、vhost 文件、凭据存放位置都各自
独立；`vigil setup` 不会碰 `vigil-dashboard.service`，反之亦然。

内置后台同样遵守本页最后一条铁律 —— **源码里没有任何一台机器的信息**：
域名、webroot、显示名、地图坐标、后台入口列表全部来自 `dashboard/config.json`，
`public_host` 还是占位值时安装脚本直接拒绝安装。它和本页一样由
`core/sourceaudit.py` 在发布关卡里强制检查。细节见
[dashboard/README.md](../dashboard/README.md)。

### 管理后台地图的手势：已停用，改用按钮

管理后台那张实时地图**关掉了拖拽 / 捏合 / 滚轮缩放**，放大缩小收敛到
`#zoom-in` / `#zoom-out` 两个按钮（开关在
`dashboard/frontend/assets/map.js` 的 `GESTURES_ENABLED`）。

**这是交互设计上的取舍，不是 bug 修复。** 手势在这张地图上与点选、以及浏览器
自身的缩放手势互相抢事件 —— 与其留一套时灵时不灵的操作，不如先收敛到确定的
按钮，把「能放大、能缩小」做成必然。

配套有一处必须记住的细节：`home.css` 里地图容器的 `touch-action` 必须是
`pan-x pan-y`。留 `none` 的话，关掉地图手势会把**整页的触摸滚动**一起拖不动 ——
关掉的应该是地图手势，不是整页的触摸行为。

## 交互逻辑

| 路径 | 是否需要登录 | 说明 |
|---|---|---|
| `GET /` | 是 | 状态页；未登录先给登录页 |
| `POST /login` | — | 按来源地址限流（8 次 / 10 分钟）；账号或密码错都返回同一句提示 |
| `POST /feedback` | 是 + CSRF | 留言入库并走告警通道 |
| `GET /api/status` | 是 | 同一份数据的 JSON |
| `GET /healthz` | 否 | 供反代/监控探活；不返回任何状态，只回 `ok` |
| `GET /logout` | — | 清除会话 |

### 几个刻意的取舍

- **没有默认账号。** 一个自带默认登录的监控页，等于一个别人已经知道密码的管理后台。
- **不接受把密码写在参数或管道里。** 那等于同时写进 shell 历史和 `ps` 输出，
  所以 `passwd` 只走交互式终端，非 TTY 直接拒绝。
- **只保存派生值。** PBKDF2-SHA256 24 万轮 + 每次随机的盐，存进
  `secrets.json`（0600）；`config.json` 里不含密码，可以安全贴进工单。
- **登录失败不区分「账号错」还是「密码错」**，并且用户名的比较不提前返回 ——
  否则响应时间会变成账号探测器。
- **会话只在内存里**，重启即全部失效，不落盘；默认 1 小时。
- **页面完全自包含**，不引用任何外部 CSS/JS。一个在断网机器上显示不出样式的
  状态页，恰好是在你想确认机器是否正常时最没用的那个。
- **只监听回环。** 对外由已经在那儿的 Web 服务负责 TLS；让这个进程直接对外
  就意味着自己实现一遍 TLS，而「差一点」的 TLS 会让它变成全机最薄弱的一环。
- **生成的配置先过 `nginx -t`**，不通过就撤回 —— 一段写坏的反代配置会把
  整台机器上所有站点一起带走。
- **不覆盖别人的 vhost。** `vigil web install` 只在目标文件带本程序生成标记
  （`# >>> vigil web (generated; ...)` / `# <<< vigil web <<<`）时直接写入；
  否则**拒绝**并给出文件路径与 `--force` 方式。`vigil web uninstall` 同样只删
  自己生成的文件 —— 文件名是 `<域名>.conf`，面板也会这么命名，所以只认标记。

## 主机信息一律运行时获取

主机名走 `socket.gethostname()`；域名、端口、上游地址全部来自配置；
**源码里没有任何主机、域名或路径**。反代配置也是从配置生成的，没配域名时
`server_name` 就是 `_`，不会凭空出现一个域名。这一条由 `sourceaudit` 在
发布关卡里强制检查。

同一条铁律也适用于 [内置管理后台](../dashboard/README.md)：它的域名、
webroot、显示名与地图坐标同样来自配置，源码里一个真实值都没有。
