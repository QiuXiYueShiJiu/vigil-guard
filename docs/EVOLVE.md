# 自修正

`vigil evolve` 是一个**有边界**的自我改进循环，外加一个专门盯着它的监控进程。
本文说明它被允许做什么、依据什么做决定、以及每一条限制是为了防住哪一种翻车。

## 一句话模型

**读本机真实流量 → 据此改进自己的判定 → 评估改动的效果 → 没用的撤掉 → 上报。**

## 两个层级

| 层级 | 能改什么 | 默认 | 约束 |
|---|---|---|---|
| 第一层 · 行为数据 | 诱饵路径表（运行期） | **开** | ≥8 次命中且≥3 个独立来源；路径过严格文法 |
| 第二层 · 源码 | 唯一一个被许可的文件（诱饵表） | **关** | 单一锚点 + 行数上限 + 每日上限 + 改前备份 + 测试不过还原 + 关键文件禁碰 |

第二层要显式指定 `evolve.source_root` 并打开 `evolve.allow_code_edits` 才会生效。

## 它自己训练自己

`vigil evolve train` 是**自监督**的，没有任何人工标注：

- **正样本**：命中过诱饵的请求、随后被封禁的地址所请求的路径 —— 这些是程序
  **已经做过**的判断，读回来当标签零成本。
- **负样本**：被正常服务（2xx/3xx）的请求。
- **没有结论的 404 不参与训练** —— 否则模型只是在重新学习程序自己的拦截行为。

`vigil evolve train --bulk` 另加一份内置大语料（按**族类**组织，不是按单条路径），
把训练量从「一台机器一周攒下的几百条」提到上千条。

### 为什么不是神经网络

日志信号是「路径 + 状态码 + UA」的稀疏词袋，在本机流量上接近线性可分。
卷积网络会贵几个数量级，更要命的是**给不出人能复核的理由** —— 而一个会改自己的
安全组件，说不清为什么就不该让它改。这里用的是在线逻辑回归，每一票都能读回来：

```
explain('/.git/config') → seg0=/.git (0.55) · probedir=/.git (0.28) · depth=2 (0.28)
```

是特征名与权重，不是下标。模型是几百个浮点数的 JSON，打分微秒级。

## 怎么证明它真的会泛化

`vigil evolve novel` 把**整族**未见过命名习惯排除在训练之外，再拿它们考模型。
这里有两个必须避开的陷阱，第一版两个都踩了：

1. **阈值必须是一次判断，不是抛硬币。** 未训练的模型对任何输入都返回 0.5；
   把 `>= 0.5` 当命中，一个空白模型能拿到 100%。
2. **只看攻击不够。** 一个把什么都判成攻击的模型同样「认出」所有新攻击 ——
   而它是废的。所以同时评正常对照组，报的是两个分布的**区分度**。

实测（语料 1131 条，`ai`/`infra`/`shell` 三族整族留出）：

| | 识别率（阈值 0.70） | 区分度 | 误报 |
|---|---|---|---|
| 完全未训练 | 0/21 | **0.000** | 0 |
| 批量训练后 | **21/21** | **0.994** | **0** |

## 闭环：它评估自己改过的东西

只有训练会让它更自信，不会让它更好。采纳的诱饵若在宽限期内（默认 24 小时）
一次都没被请求，就**主动撤下**。没有这一步，采纳表只增不减。

## 资源占用

按**可用量的比例**给，不写死绝对值（「最多 200 MB」在 1 GB 小机上太多、
64 GB 机器上太少）：

| 键 | 默认 |
|---|---|
| `evolve.memory_pct` | 取**可用**内存的 5% |
| `evolve.memory_floor_mb` | 可用内存低于 96 MB 就不开工 |
| `evolve.load_ratio` | 负载超过 `核数 × 0.7` 就不开工 |
| `evolve.time_budget` | 单次运行墙钟上限 120 秒 |

systemd 侧另有硬上限：`CPUQuota=5%`、`Nice=19`、`IOWeight=10`、`MemoryMax=256M`、
`OOMScoreAdjust=800`，并明确标注**不属于告警链路** —— 出问题时它该是第一个被
牺牲的，绝不能因为它而让通知发不出去。

## 关键文件：第二道锁

许可表只允许改一个文件，但**许可表本身是可编辑的**。所以另有一份
`CRITICAL_FILES` 清单，覆盖：封禁决策与生效、观测入口、诱导面、本循环自身的
边界与资源上限、审计链、上报与脱敏、训练标签来源、全部配置、部署与单元生成、
命令入口，以及整个邮件通道。

理由很直接：**一个能放宽自己限制、或让监督自己的东西失明的 agent，就不是有边界的
agent。** 有测试专门把许可表改宽，验证它仍然拒绝落笔。

## 自修正 vs 恶意更改：靠哈希归因

完整性检查看到改动时，此前一律报 CRIT —— 包括本程序自己的自修正（`evolve` 被
允许改诱饵表）。结果是真正的恶意改动被淹没在合法自改的噪声里。现在先归因：

| 依据 | 结论 |
|---|---|
| 台账记录的「改动后哈希」**等于**该文件当前哈希 | 自修正（指名是哪一条台账） |
| 有该文件的记录但**哈希不符** | CRIT，疑似恶意更改（报出期望 / 实际哈希） |
| 无记录，但落在 `vigil update` 的部署窗口内 | 部署 |
| 其余 | CRIT，未归因 |

**哈希是唯一判据。** 不用时间戳，也不用「台账里有这条记录」—— 只要「最近有过
自改」就能给任何恶意改动当挡箭牌，那正是这条路最容易翻的车。路径也必须对上：
绝对路径、相对源码根，或（**仅当所有改动文件里该 basename 唯一时**）basename ——
否则不同文件之间哈希相同只是巧合，而不是归因。

### 台账不可伪造：链式 HMAC

归因依赖台账，台账因此成了**攻击目标**：一个谁都能追加的 JSONL 就是洗白通道 ——
追加一行「我改了这个文件，新哈希是这个」，恶意改动和已批准的自改就再也分不开，
检查还会对攻击者的改动报出「自修正（已记录）」，**比没有这个功能更糟**。

所以每条记录带 `prev`（上一条的 MAC），文件成为**链**；MAC 是 `secrets.json`
里密钥（`0600`，在仓库之外）下的 HMAC-SHA256。删掉一条、重排、从中间抽掉一条，
链接都会断并被**发现**；没有密钥就无法为追加的记录生成合法的 MAC，而**无法验证
的记录永远不会被用来解释一次改动**。

只有哈希链是不够的：重算一串哈希不需要任何秘密，愿意重写文件的人就能造出一条
自洽的链。**秘密才让链有意义。**

**校验失败不是「忽略台账」。** 链断掉时，归因把**所有**改动都当作未归因，并报出
断在哪里 —— 在这里 fail-open，就是把洗白通道升高一层。

### 归因窗口，以及「链证明不了什么」

- **时间窗口**（`checks.self_integrity.attribution_window_seconds`，默认 24 小时）：
  三个月前的一次自修正不能为今天的改动背书，否则每一次后续改动都能永久躲在它
  的影子里。超出窗口的记录按未归因处理。
- **边界写在代码里，也写在这里**：链证明的是「**已加链**的记录没有被改写、删除
  或重排」，它**证明不了**「没有旧格式（无 MAC）的行被追加」—— 链的全部意义
  就在于可以被**追加**。这类不能为自己作证的记录会被计数，并且**永远不会**被
  用来解释一次改动；断链时，断点位置（检查窗口内的 1-based 行号）会一并报出。

## 上报

改动写入本地只增台账（`vigil evolve status` 看，`rollback <id>` 逐条回滚），
同时 POST 到收集端（`evolve.report_url`，**默认留空**）。发送前脱敏：
`ip`/`host`/`domain`/`path`/`webroot`/`token` 一律丢弃，服务端再校验一次。

这条通道的意义是把一台机器的经验变成所有机器的默认值 —— 也就是「集中调整」。

## 监控进程

`vigil-watchdog.service` 从**外部**看循环：读它写的同一批文件，不听它自己的说辞。
触发条件包括一小时内改动次数异常、台账写入失败、源码自改超限、采纳条数超限。
命中严重项直接发告警，并给出「怎么停下来」的三步。

## 命令

```sh
vigil evolve status      # 现状、已采纳的改动、资源预算
vigil evolve scan        # 只看证据，不改任何东西
vigil evolve plan        # 它打算做什么，以及依据
vigil evolve apply --all # 执行（--dry-run 预演；执行前必发邮件）
vigil evolve rollback ID # 撤销一条
vigil evolve train       # 自监督训练（标签来自本机处置结果）
vigil evolve train --bulk# 加大语料，并报告对未见族类的识别能力
vigil evolve novel       # 用整族未见过的攻击测泛化
vigil evolve outcomes    # 回看自己的改动有没有用
vigil evolve loop        # 跑一轮完整闭环（供定时器调用）
vigil evolve watchdog    # 检查循环是否失控
```
